# 首次部署初始化向导实施计划（2026-10-10）

> 本文档为大型改动的计划文档（AGENTS.md 工作方式要求）。本次改动由 /goal 指令直接驱动实施，
> 计划与实现同会话完成；如需回溯设计取舍，以本文档 + 代码注释为准。

## 1. 背景与现状（改造前）

- 首次部署（无 appsettings.json / 无 Quantum 节）时，`SystemConfigHelper.GetSetting()` 自动生成
  **随机用户名/密码**并打印到控制台（Docker 部署需 `docker logs` 找凭据），数据库固定 SQLite 随机文件名。
  新用户无法自主选择账号与数据库，也看不到平台自带能力。
- `SystemConfigController.Install`（匿名 POST /api/SystemConfig/install）形同虚设：
  `GetSetting()` 永不返回 null（缺失即自动生成），`Install` 恒抛「系统已经初始化过了」，是死代码。
- 新库初始化时 `ScriptTaskSeeder` 把 `Quantum.Web/scripts/` 顶层全部 `.cs` **无条件**登记为停用任务，
  用户没有选择权；脚本是做什么的也没有任何清单可看。
- 结果：新用户「登录难（凭据在容器日志里）、选库难（要手改 json）、上手难（一屏停用任务不知道干嘛）」。

## 2. 目标（验收口径）

1. **首次部署引导创建登录账号密码**：Web 管理端打开即进入初始化向导，用户自定义账号密码；
2. **引导选择数据库**：SQLite（零配置）/ MySQL（连接串）二选一，可先做连接测试再落盘；
3. **列出项目自带脚本、勾选初始化任务**：向导列出随应用分发的脚本（含用途说明），用户勾选后建任务；
4. 全流程不看容器日志、不手改配置文件即可完成部署并登录使用。

## 3. 设计

### 3.1 「首次部署」判定

`Setting`（appsettings.json 的 Quantum 节）新增两个字段：

- `SetupCompleted`（`bool?`）：`false` = 等待初始化向导；`true` = 已完成；**缺省 null = 存量部署，按已完成处理**
  （保证已上线实例升级后不会被向导劫持）。
- `SetupPendingScripts`（`string`）：`null` = 无待办；非 null（含空串）= 向导已选定脚本清单待落库
  （空串 = 明确不建任何任务）。用于「切换数据库需重启」场景的跨重启补种，见 3.4。

`NeedSetup = SetupCompleted == false || UserName/PassWord 为空`。

自动生成路径（首次无配置）行为变更：机器侧密钥照旧随机生成（JWT 密钥/Issuer/Audience/通道主密钥/
DB 文件名/端口），但 **不再生成随机登录账号密码**，`SetupCompleted=false`，控制台输出改为引导打开
Web 初始化向导。`appsettings.example.json` 的 UserName/PassWord 改为空串（空 = 走向导）。

### 3.2 后端 API（新 `SetupController`，`/api/Setup/*`，全部匿名）

| 端点 | 说明 |
| --- | --- |
| `GET  /api/Setup/status` | `{ NeedSetup, DBType, DBAddress, Scripts[] }`；Scripts 为自带脚本清单（FileName/Name/Description） |
| `POST /api/Setup/test-database` | 按 `{DBType, DBAddress}` 试连数据库（MySQL 开连接握手；SQLite 校验文件名与目录可写），返回成败与原因 |
| `POST /api/Setup/complete` | 一次性提交：`{ UserName, PassWord, DBType, DBAddress, Scripts[] }` → 建账号、选库、按勾选建任务 |

`complete` 语义：

- 仅 `NeedSetup` 时可用；已初始化再调用抛 `BusinessException`（防未授权改密/接管账号——安全红线）。
  「检查 + 写配置」在 `SystemConfigHelper.UpdateSetting` 的写锁内原子完成，杜绝并发双初始化。
- 校验：用户名非空且非保留名（SetSetting 兜底）；密码非空且 ≥6 位；DBType ∈ {SQLite, MySql}
  （大小写归一）；MySQL 连接串非空；SQLite 文件名经 `SafeFile.Resolve` 落在 `db/` 内（防路径穿越）；
  `Scripts[]` 只接受当前自带脚本清单内的文件名（白名单求交，防穿越与越权注册）。
- 写配置：UserName/PassWord/DBType/DBAddress/`SetupCompleted=true`，并抬升 `UserTokenNotBefore`
  （与改密同款，作废任何此前签发的令牌）。
- 建任务（勾选的脚本）：与 `ScriptTaskSeeder` 同规格——门禁+Roslyn 校验 → 源码复制到运行目录
  （已存在不覆盖）→ `TaskModel` 登记（`Enable=false`，脚本需先配环境变量再启用）。
- **数据库未变更**（与本次启动的 DBType/DBAddress 相同）→ 立即建任务，返回 `RestartRequired=false`；
  **数据库变更**（如 SQLite→MySQL）→ 选择写入 `SetupPendingScripts`，返回 `RestartRequired=true`，
  下次启动在新库上自动建任务（见 3.4）。向导 UI 明示「重启后生效」。

`SystemConfigController.Install` / `SystemConfigService.Install` 死代码删除（被本流程取代）。

### 3.3 登录链路

`LoginService.Login` 在未初始化（账号/密码为空）时提前抛出「系统尚未完成初始化，请先在 Web 端完成
初始化向导」，不再落入通用「用户名密码错误」。

### 3.4 脚本任务播种状态机（`SetupTaskInitializer`，Startup 建库后调用一次）

```
SetupCompleted == false        → 不播种（等向导在当前库直接建）
SetupPendingScripts != null    → 按清单建（可为空 = 不建），建完清回 null
数据库为本次新建 且 无上述状态   → 全量播种（存量零配置行为不变，兼容老部署/迁移用例）
其余                            → 不动
```

即：老部署（无 SetupCompleted 键）行为完全不变；新部署由向导决定播种范围；
切库场景靠 `SetupPendingScripts` 跨重启把「用户勾选」带到新库，不会退化为「全量塞进来」。

### 3.5 Web 前端（quantum-web）

- 新路由 `/setup`（免登录，`name: 'setup'`），新页面 `view/setup/index.vue`：三步向导
  （① 创建登录账号 → ② 选择数据库 → ③ 选择自带脚本建任务）+ 完成页；
  风格沿用「风格B」（暗色玻璃卡片），与登录页同款布局。
- 登录页加载时调 `GET /api/Setup/status`，`NeedSetup` 为真则自动跳转向导；
  向导完成且无需重启时自动用新账号登录进入平台；需重启时提示重启后再登录。
- 路由守卫放行 `/setup`（无 token 可达）；`/setup` 在已初始化状态下自行跳回登录页。
- 纯逻辑抽到 `src/utils/setupWizard.js`（表单校验/是否需重启/脚本选择摘要），配 vitest 单测。

### 3.6 安全边界

- 向导端点匿名，但 `complete` 仅在 `NeedSetup` 期间一次性有效，完成后即关闭（改密必须走登录后的
  `/systemconfig/password`）；`test-database` 同样仅未初始化期可用，并按 IP 固定窗口限流
  （复用 `MemoryObjectCache` 限流风格），防止被当成内网探测跳板。
- 脚本文件名、SQLite 文件名一律白名单/SafeFile 校验，杜绝路径穿越。
- 不改门禁三级扫描、不放宽上传/脚本链路登录要求；HTTP 恒 200 信封不变。

## 6. 风险与回滚

- 存量部署兼容性：`SetupCompleted` 缺省按已完成处理，行为零变化；唯一行为差异是「无配置首启」
  不再打印随机凭据（改为走向导），README 已同步。
- 向导完成即写真实凭据进 appsettings.json（与现改密链路同一原子写入，WriteThrough+rename）。
- 回滚：新字段对旧版本透明（旧版读配置忽略多余字段），回退二进制即回到旧行为。
