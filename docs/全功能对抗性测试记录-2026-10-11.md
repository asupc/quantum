## 二、被击穿的修复（对抗性测试的核心产出）

这一节记录「修了但没修住」的案例。全部由独立验证者在真机上击穿，修好后再由第三方验证者复核。

### 1. 外触内执深载荷被静默丢弃（击穿两次）

现象：`POST /api/OpenTriggerTask/{secret}` 提交嵌套 >32 层的 JSON，端点返回「执行成功」、
运行记录记 `Succeeded/None`，而**脚本收到的是 `null`**——载荷被悄悄丢弃且报告成功。

根因链（两轮才挖到底）：
1. 首轮以为问题是「`JsonConvert.SerializeObject` 写入侧无深度上限 → 深嵌套爆栈」，于是加了
   `ValidatePayload`（深度/节点上限）。**验证者指出该守卫根本不可达**：载荷在 MVC 绑定阶段
   就失败了。
2. 次轮换成 `[FromBody] JToken`。**仍被击穿**——MVC 的 Newtonsoft 输入格式器内部固定
   `JsonTextReader.MaxDepth = 32`，与参数类型无关；再叠加本项目
   `SuppressModelStateInvalidFilter = true`，绑定失败既不报错也不进 ModelState，直接变成 `null`。
   验证者实测深度 33/40/64/1000 全部「成功 + 载荷为 null」。
3. 最终修法：**该端点彻底不走 MVC 绑定**——控制器直接读 `Request.Body` 并
   `JsonConvert.DeserializeObject<JToken>(raw, new JsonSerializerSettings { MaxDepth = null })`
   （JToken 解析是迭代式，已实测 10 万层不爆栈），空体/`null`/坏 JSON 一律明确报错；
   再由服务侧 `ValidatePayload` 判定深度（按**容器嵌套层数**计，属性节点与标量叶不占层）、
   节点数与序列化长度。

第三轮独立验证覆盖 8 组探测（深度 30→300 万、数组/混合嵌套、10001 节点、300KB→20MB 单叶、
空体/坏 JSON、10 种 Content-Type、构造式表单截断、40 并发）：**未再找到任何「报成功但载荷消失」的深度**，
且每个被接受载荷的 `PAYLOAD_LEN` 与提交字节数逐一对齐。（该轮真机探测的临时产物已随验证目录清理，
仓库内保留的是同等口径的确定性回归用例：`OpenTriggerPayloadBindingTests` 等。）

### 2. 飞书富文本只转义了「标记内」文本（击穿一次）

首轮修复给 `{{…}}` 标记正文加了 markdown 元字符实体化。验证者指出：**标记之外的裸文本原样下发**，
`plain [x](https://evil.example) plain` 与 `plain <font color='red'>…</font>` 逐字存活——
即用户仍能在卡片里自造链接、注入 `font`/`at` 构造；`{{link:…}}` 的地址侧也从未校验。

修法：`ToLarkMd` 对三段普通文本同样转义；`IsSafeHttps` 追加拒绝控制字符/空白/`()[]<>"'` 反引号/反斜杠
与实体形态（`&#…`、`&amp;` 等，防「渲染方先解码实体再解析 markdown」的二段构造）。
第三轮验证逐项复核 8 组输入：注入形态全部失效，合法地址（含 `~`、query、百分号编码）仍正常渲染。

## 三、真实缺陷与修复（按严重度）

### 严重：任务脚本可越权读写任意文件与平台数据库（现场端到端实证）

- `Microsoft.Data.Sqlite` / `Microsoft.EntityFrameworkCore` 在编译引用白名单内，却不在门禁命名空间黑名单里。
  脚本用 `new SqliteConnection("Data Source=../x.db")` 即可在 `scripts/quantum` 之外建库写库；
  更严重的是可直读直写平台库（`t_env`、`t_external_push_credential`、`t_channel_account`、`t_app_refresh_token`）。
  实测记录：`ESCAPE-WRITE-OK`、`DB-READ-OK tables(40)=…t_env,t_external_push_credential…`、
  `DB-WRITE-OK rows=42`，且**运行记录报成功**。
- 同类越权面：非 `System.IO` 命名空间的文件 API（`System.Xml.XmlWriter.Create(path)`、
  `XDocument.Load/Save`、`WebClient.DownloadFile`、`TextWriterTraceListener`、`ResourceWriter`、
  `TarFile.ExtractToDirectory`）、反射桥（`x.GetType().GetMethod(...)` + `System.Delegate.CreateDelegate`，
  因为 `System.Type`/`System.Delegate` 不在黑名单，成员签名也不检查）、
  `System.Runtime.CompilerServices.Unsafe`、`System.Net.WebSockets`/`SmtpClient`/`Ping`（号称封了裸 socket 却漏了这些）、
  `System.Threading.Timer`/`ThreadPool`、`System.Diagnostics.Debugger`。
- 修复：门禁新增成员级/类型级/命名空间级规则 + **实参级扫描**（唯一放行 `Data Source=:memory:` 的
  Sqlite 用法，attch/VACUUM INTO、`LoadExtension`、EF 裸 SQL 入口全部拦截），
  并同步 `DescribeRules`/`DescribeReferenceWhitelist` 防止 AI 提示词与实际规则漂移。
  101 个新用例（8 类逃逸全部先红后绿），**35 个自带脚本全部仍通过门禁**，`Microsoft.Data.Sqlite` 的
  文档化 `:memory:` 能力保留。
- 诚实结论（已写入报告）：**这类门禁永远不可能成为对抗性沙箱**——脚本与宿主同进程同权限运行，
  黑名单是攻击者主导的军备竞赛。真正的边界需要进程外隔离（受限 OS 身份 + 只读根文件系统 + 无网络 +
  仅经 IPC 走门面）。本次的价值是把已证实可用的逃逸口全部堵上、并把「防误用」定位说清楚。

### 高：进程级崩溃 / 资源耗尽

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 深嵌套 JSON 序列化爆栈 | `JsonConvert.SerializeObject` 递归爆栈 → `StackOverflowException` 不可捕获，**进程直接死**（已用探针复现「测试主机进程崩溃 : Stack overflow」） | 见「被击穿的修复 #1」：迭代式遍历 + 深度/节点/长度三重上限 |
| `/ws/app` 无凭证连接不回收 | 不足 token 的 upgrade 返回 101，且未鉴权连接不进注册表、心跳扫不到；实测单条常驻 **357s+**，43 条并发无一被回收 | 首帧鉴权改为**绝对期限**（默认 30s，不随收帧续期），过期即断；实测 30.0s 被回收，而「2s 内完成首帧鉴权」的合法路径可存活 47s+ |
| 心跳回收可能永久挂住 | `CloseAsync(..., CancellationToken.None)` 对黑洞对端可无限等待，`PeriodicTimer` 循环体不返回 → **此后所有心跳巡检停摆** | 关闭操作加超时并竞争 `Task.Delay`，超时 `Abort()`；单连接失败隔离，不影响同批其它连接 |
| 任务 HTTP 无 SSRF 边界 | `ctx.Http`/`ctx.File.DownloadAsync` 只校验 `http` 前缀且 `AllowAutoRedirect=true`，可打 `127.0.0.1`、`169.254.169.254`、私网，公网可 302 引向内网 | 新增 `NetworkGuard`（连接级 + 逐请求级双校验、DNS 全量公网判定、关自动重定向）；**并加 `TaskNetworkAllowlist` 运维白名单**，否则会误伤自带脚本（见下） |
| SSE `tool_calls.index` 无上限 | 恶意/异常供应商回 `{"index":2000000000}` → 一次分配 20 亿对象 OOM | 索引上限 64，越界块丢弃并记日志 |
| 脱敏正则二次方爆炸 | `\w*(?:password\|…)\w*` 在长词串上 O(n²)，输入是未截断的脚本异常消息（1MB 即卡住一个核） | 输入先截断（16KB）+ 正则超时 + 超时降级不阻断链路 |
| 分页无上限 / `Skip` 溢出 | `PageSize=2000000000` 原样执行；`PageIndex=100000*PageSize=1000000` 的 int 乘法溢出成负 OFFSET（SQLite 当 0、MySQL 报错） | `BaseQuery` 上下限 clamp + `long` 计算收敛；导出链路依赖的 999999 仍在限内 |

**注意（本次改动引入并被修正的功能回归）**：SSRF 边界最初直接把私网/回环全部拒绝，
会**打断自带脚本**——`qBittorrentAdd.cs`、`dygangs.cs`、`music_search.cs` 都要求填
`http://192.168.x.x:8080` 这类局域网地址。已补 `Setting.TaskNetworkAllowlist`
（设置页新增「任务内网白名单」，默认空 = 只允许公网）并把三个脚本的头部说明改为「内网地址需先登记」。
安全默认值保持不变，功能靠显式登记恢复。

### 高：凭据与信息泄露

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 初始化向导泄露库密码 | 匿名 `GET /api/Setup/status` 在未初始化期原样返回 `DBAddress`（MySQL 连接串内含 `Pwd=`） | 返回值掩码化，保留结构、去掉口令（含引号包裹口令的分号截断场景） |
| SQLite 库名可注入连接串 | `ValidateSqliteFileName` 放行 `;`/`=`/`:`，配合 `"Filename=db/" + DBAddress` 可指定任意绝对 `Data Source`（任意文件创建/覆盖）或 `Mode=Memory` | 向导校验拒绝这些字符（不改启动期消费口径） |
| 脚本源码无长度上限 | `PUT /api/Task/scripts` 接受 6MB 源码，同步编译无超时、产物按哈希缓存（容量 64） | 上限 1MB，超限明确报错（保存与上传两路） |
| 日志删除路径无穿越校验 | 读路径走 `SafeFile.Resolve`，删除路径却直接 `File.Delete("./logs/" + LogPath)`（非对称防御） | 删除路径同样走 `SafeFile.Resolve`，脏行跳过但不阻断整批 |
| 飞书帧长度整数溢出 | `offset + length` 用 int 相加，可溢出为负绕过截断检查 → `IndexOutOfRangeException` 逃出连接循环 | 改为长整型剩余量比较并统一抛协议异常；另加 20 万条随机缓冲模糊测试（固定种子，可复现，仅允许协议异常） |
| 微信线水位分隔符冲突 | 会话名含 `,` 会与编解码分隔符冲突，污染**其它**会话的未读水位 | 版本化前缀 + 转义，旧格式键逐字节兼容读回 |
| 登录页页脚 `v-html` | 匿名接口返回的 `Footer` 原样 `v-html`，管理端还宣传「支持 html 标签」→ 预认证页 XSS，而 JWT 在 localStorage | 新增零 DOM 白名单重建式净化器（保留有限格式，剥离事件/脚本/危险协议），管理端文案同步 |
| WebSocket 握手令牌进 URL | `?token=` 进代理/访问日志，且 401 只重连不登出 | 改为首帧 `auth`（后端本就支持），401/1008 判定为终态并复用统一登出逻辑 |

### 中：并发与状态一致性

| 缺陷 | 现象 | 修复 |
|---|---|---|
| `CacheManager` 读穿可钉住旧快照 | 读者 miss → 查库 → 期间写者 `Refresh`（Remove 空操作）→ 读者 `Set(old)` → **旧数据长期生效**（脚本读到旧环境变量、启停判定用旧行） | 每类型代际计数：`Refresh` 自增，`Get` 仅在代际未变时写缓存 |
| 配置 memo 撕裂导致密钥轮换静默失效 | 「读到的文本」与「解析出的 Setting」来自两次读，可能配对成「新文本 + 旧配置」并被 memo 永久命中 → 改密后旧签名密钥继续有效 | 文本只读一次、按同一文本解析、且仅在文本仍为当前值时发布 memo |
| 外触配置写后不刷新缓存 | 新建/删除外触配置后 `Trigger` 仍读旧快照（「保存成功」后立即触发报「未找到相关配置」） | 新建/更新/删除路径统一 `CacheManager.Refresh<OpenTriggerTask>()` |
| WS 帧非字符串字段抛异常 | `{"type":123}`、`{"type":"auth","token":123}` 等触发 `JsonElement.GetString()` 的 `InvalidOperationException`，且收发循环只捕获 `WebSocketException` | 统一 `GetStringOrNull`（非 String 类型返回 null），合法帧行为不变 |

### 其余（对抗性测试覆盖到、结论为安全的部分）

以下是**验证为安全**并记录了具体防线的高危面，避免后续重复怀疑：

- **Open AppKey 令牌无法穿越任何受保护端点**（含仅挂 `[CustomAuthorizationFilter]` 的控制器）：
  `ValidateLogin` → `IsLoginPrincipal` 正向要求 `Name == 当前配置账号` 且 `TokenPurpose == "User"`。
  审计中有代理一度报「8 个控制器可被 AppKey 令牌读」为高危，经契约测试与代码复核判定为**误报**，
  已在记录中标注（这条误报的价值在于提醒：不要按属性组合推断结论，要看过滤器到底调用了什么）。
- **PushKey 隔离完好**：不产出身份、失败不可区分、256 位密钥、SHA-256 常数时间比较、
  写入固定 `external:{credId}:{hash}` 会话且为**发送方向**，不进指令队列。
- **通道出网**是全仓最严的边界：host 白名单 + 公共 IP 钉扎 + 禁重定向 + 响应体积上限；
  入站消息一律只收文本，无附件下载面（因此不存在「入站消息 SSRF」）。
- **空 id 列表的删除语义**：所有批量删除/启停路径逐一核实，空列表一律「什么都不删」，无「空即全删」。
- **脚本门禁的语义级扫描**确实挡住了别名/`using static`/`var`/`namespace` 改写级绕过
  （`using static System.IO.File;` + `ReadAllText`、`typeof(Process)`、`Marshal`、`DllImport`、
  `Expression<>`、`Assembly.Load`、`Thread.Start` 等全部实测被拦）——问题不在「改名能绕过」，
  而在上面「未列入黑名单的等价能力面」。
- **前端 HTML 汇聚点**除页脚外均为「先转义后拼接」；聊天媒体 URL 有协议白名单；
  `/^https?:\/\//` + `noreferrer` 的通知跳转保持在正确口径。
- **安卓端**无 WebView、无日志拦截器、`allowBackup=false`、不覆盖 TLS 信任；
  已修的是：扫码登录**无确认即授权**（可被恶意二维码钓取 7 天管理端令牌，已加确认弹窗）、
  WS 帧类型不耐受导致静默丢帧（已加兼容解码）、换服务器不清旧令牌（已按 host:port 变更清理）、
  以及「发送失败无任何用户可见提示」（`toast` 无人消费，已接 Snackbar + 重发）。

## 四、误报与「看起来危险但不可达」的判定

记录这些同样重要——避免下次重复投入，也避免把设计取舍当漏洞：

| 报告 | 判定 | 依据 |
|---|---|---|
| 「Open AppKey 可达 8 个仅挂 CF 的控制器」 | **误报** | `ValidateLogin` 内含 `IsLoginPrincipal`，AppKey 主体名被显式拒绝；已有契约测试锁定 |
| 「飞书 wss 帧溢出可打死进程」 | 降级 | 溢出点/上限已在连接循环内被 `ChannelProtocolException` 接住，影响是重连不是进程死亡 |
| 「`Logs/statistics` 的 `days` 无上限」 | 真实但低危 | 触发 `ArgumentOutOfRangeException` → 干净的信封 500，未挂死 |
| 「脚本门禁是沙箱」的预期 | **设计澄清** | 门禁定位是「防误用 + 抬高成本」，同进程同权限运行不可能成为边界；已在代码注释与文档写明 |
| 「`docker stop/restart` 可经通道私聊触发」 | 待产品决策 | 属单用户设计下「私聊共享 App 指令能力」的既有语义，非本次改动引入；已在文档标注风险 |
| 「Android 明文 HTTP + 365 天刷新令牌」 | 待产品决策 | 客户端显式支持 `http://` 自建服务，属部署取舍；改 NSConfig 会影响内网自建场景 |

## 六、遗留与建议（未在本次实施）

1. **脚本执行的真实隔离**：同进程跑不可信脚本，门禁只是护栏。建议后续把执行移入独立进程 +
   受限 OS 身份 + 只读根文件系统 + 无网络（仅经 IPC 走门面），并加 CPU/内存/墙钟/句柄上限。
2. **通知/日志中的密钥**：`ExceptionFilter` 仍会把 `Request.QueryString` 写入日志，外触 Secret 走 URL 路径
   也会落到代理/访问日志。建议逐步迁移到 Header/Body 传参并做路径脱敏。
3. **通道私聊的指令面**：若机器人可能被陌生人私聊，`docker stop/restart` 这类系统指令需要收窄
   （`ChannelQuickReplyService` 的允许清单当前在入站链路上未被调用）。
4. **Android 传输安全**：`usesCleartextTraffic=true` + 365 天刷新令牌组合，在共享网络下风险明确；
   若要支持自建 http 服务，建议同时提供「仅对已登记主机允许明文」的 network security config。
5. **告警/配额**：`t_log`、上传目录、`t_channel_inbox` 等缺少保留期清理，长期运行会持续增长。
