# 单用户登录与外部凭据契约

> 2026-09-29 起的现行认证、任务与运行历史口径。历史方案和审计记录仍按其编制时状态保存。

## 登录身份

- 平台只有 `Quantum:UserName/PassWord` 一组登录账号，Web 与 App 共用。新 access token 含 `Name`、`LoginTime` 和 `TokenPurpose=User`；App 另含 `DeviceId`，不再签发角色声明。
- 受保护的 HTTP 端点先验签，再确认用途为登录、主体与当前配置账号一致、`LoginTime` 有效且不早于改密下限。拒绝返回 HTTP 200、`ResultModel.Code=401`。`[AllowAnonymous]` 仅用于登录、刷新、扫码票据、公开页脚、安装和独立外触等已有匿名入口。
- 原 Web/App access token 仅在原有效期内兼容：没有 `TokenPurpose` 时仍须有当前账号名和有效 `LoginTime`；只有 `Name` 的令牌不能登录。兼容判定不读取旧 `Manager` 值。旧 App 版本可继续调用已支持的端点，但需单独做真机过渡验收。
- `/ws/app` 的 URL 令牌与首帧 `auth` 均使用相同登录判定；URL 令牌无效时握手返回 HTTP 401，首帧无效时发送错误帧并关闭连接。
- 改密将 `UserTokenNotBefore` 与旧配置键 `ManagerTokenNotBefore` 同写为同一签发下限，读取时取两者较大值。旧登录 access token 与 App refresh token 同批失效；refresh 时还会独立核对签发下限，以防数据库吊销标记写入失败时旧令牌续签。两键并存用于回退旧服务端；不能单独回滚到会读取已删除数据库列的版本。

## 外部凭据

- Open AppKey 只可换取 `TokenPurpose=Open`、固定主体名 `______App-Key-Auth` 的短期 JWT；该主体名不能配置为登录账号。Open JWT 不能调用任务、脚本、环境变量、日志、AI、设备、系统设置、媒体下载，也不能加入 WS 广播。
- `PushKey {credentialId}.{plainSecret}` 只用于外部推送端点，不产生登录 JWT。外触 Secret 和通道回调只作用于各自入口，不授予登录能力。
- 上传扩展名白名单、脚本三级门禁、SafeFile 路径限制及现有密码限流仍生效。HTTP 业务信封与 App refresh 轮换、设备解绑和重放处置口径不变。

## 任务与数据

- 登录账号可查看、编辑、执行、导入导出全部任务，并读取全部运行历史和日志。任务、导入导出 JSON 与运行历史不再有角色字段。旧任务 JSON 的 `Manager` 字段被忽略。
- SQLite 与 MySQL 的 `RemoveTaskRoles` 迁移删除 `t_task.Manager` 和 `t_task_run.ManagerSnapshot`；Down 仅以 `false` 重建列，无法恢复旧角色位。部署前备份数据库与配置，并用旧库副本演练迁移。新模型的 `EnsureCreated` 不创建这两列。
- 已在本地 SQLite 测试库和隔离的 MySQL 8.4 容器中验证 Up/Down；MySQL 以旧列分别为 0/1 的任务与运行记录演练，删列后记录保留，Down 两列以 0 重建。生产库仍须单独备份与演练。
- 先部署具备登录用途校验的新服务端，再发布 Web 和 App。删列迁移与本版服务端须一同部署；回退时恢复同一时间点的旧数据库、配置和旧服务端。
- 本地端到端验证覆盖 Web/App 登录、HTTP 与 WS 的凭据用途、改密吊销、Android 模拟器上的旧版 APK 过渡和扫码票据授权。生产数据库备份、物理设备摄像头与后台通知仍须在目标环境单独验收。
